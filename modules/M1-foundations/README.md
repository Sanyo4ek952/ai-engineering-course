# Модуль M1 — инженерная база frontend (недели 1–4)

**Статус:** утверждён в программе v1.0, 2026-11-05. **Нагрузка:** 32–40 часов, 8 занятий (ориентир по 4–5 часов).

## Результат модуля
Собрать работающий frontend списка обращений SupportDesk AI и самостоятельно объяснить типы, контракт API, state, URL, кэш, ошибочные сценарии и границы компонентов. Начинаем с mock API; реальная БД и auth появятся в M2.

## Маршрут и сдаваемые материалы

| Урок | Тема и самостоятельная практика | Доказательство |
|---|---|---|
| M1-01 | Требования, роли, use cases и HTTP-контракт | `SPEC.md`, `API-CONTRACT.md`, 3 негативных случая |
| M1-02 | TS-модели данных, strict, discriminated unions, runtime validation | Типы и валидаторы ответа, примеры успешных/ошибочных payload |
| M1-03 | React-компоненты и UI состояния загрузки/ошибки/пустого списка | Страница списка с mock API, скриншоты состояний |
| M1-04 | RTK Query: аргументы, URL, пагинация, кэш | Фильтр/поиск/пагинация, отсутствие чужих данных при смене аргументов |
| M1-05 | Архитектурные границы, FSD по необходимости, ADR | схема зависимостей, ADR с альтернативами |
| M1-06 | Тесты React и контракта API | тесты загрузки, ошибки, фильтра, невалидного ответа |
| M1-07 | Мутации, `providesTags`/`invalidatesTags`, гонки запросов | изменение статуса и корректное обновление списков |
| M1-08 | Интеграция, code review, независимая защита | воспроизводимый запуск, тесты, ответы 2–4 вопросов |

## Правило работы
Сначала студент сам формулирует решение и показывает попытку; затем AI может объяснять, помогать с реализацией и проводить ревью. Для финальной проверки — самостоятельная задача/защита без подсказок. Codex не должен выполнять за студента самостоятельную часть и не должен автоматически помечать урок завершённым.

## Приёмка
Для каждого урока заранее применять `RUBRIC.md`: 40% поведение/артефакт, 30% самостоятельное понимание, 20% надёжность, 10% качество работы с AI; при неприменимости критерия объявлять изменённые веса до работы. Ориентир ≥80/100, отсутствие критических проблем безопасности; без доказательств `needs-evidence`. Проверка осуществляется по результату, не по времени.

## Исходные пробелы P0
Повторно проверяем в реальных заданиях: коды HTTP 401/403/409/500, разницу UI/server state, инвалидацию по мутации, тестирование негативных сценариев и ревью AI diff. Закрывать только после самостоятельного доказательства.
