# SPEC.md — SupportDesk AI: обращения

**Урок:** M1-01 · **Версия:** 0.1 · **Статус:** DRAFT / совместная сборка после устной самостоятельной попытки, НЕ сдача.  
**Дата:** 2026-11-10 · **Источники:** ответы студента в проектном чате и комментарии наставника. Первая попытка сделана устно; полного самостоятельного файла до AI не было.  
**Маркировка происхождения:** [С] — предложено студентом; [Н] — добавлено или уточнено наставником; [С+Н] — идея студента, редакция наставника. Ни один пункт не считать самостоятельным доказательством, если он переработан наставником.

## 1. Назначение и границы

**[С]** CRM собирает и структурирует обращения клиентов, их контакты, запросы и историю, чтобы менеджеры могли обрабатывать обращения и не терять информацию.

**[Н]** Первая версия SupportDesk AI — общая CRM обращений; бронь жилья, наличие товаров, интеграции и товарные каталоги не входят в первый срез. Фича урока M1-01 — прежде всего **список обращений и контракт чтения**; функции переписки и auth представлены как контекст будущих этапов.

**Акторы:** [С] менеджер; [Н] неаутентифицированный посетитель, администратор/ответственный за выдачу доступа (пока вне scope этой фичи).

## 2. Функциональные требования

| ID | Требование | Авторство | Scope |
|---|---|---|---|
| FR-01 | Менеджер открывает список обращений и видит данные существующих обращений | [С+Н] | M1 |
| FR-02 | Менеджер может изменить статус обращения; после сохранения обращение находится под новым фильтром, история не удаляется | [С+Н] | M1/M2 |
| FR-03 | Менеджер фильтрует обращения по статусу; запрос выполняется сервером, при изменении фильтра страница становится первой | [С+Н] | M1 |
| FR-04 | Без действительной сессии менеджер не получает защищённые обращения и видит предложение войти повторно | [С+Н] | M2, mock в M1 |
| FR-05 | Менеджер может отвечать клиенту; сообщение имеет видимые состояния отправки, успеха и ошибки | [С+Н] | последующий этап |
| FR-06 | Менеджер ищет обращение по имени клиента и перемещается по страницам списка | [С+Н] | M1 |

**[Н]** Для M1-01 в первую очередь проверяем FR-01, FR-03 и FR-06. Наличие FR-02/04/05 в общей спецификации не означает, что их нужно реализовать сейчас.

## 3. Нефункциональные требования (предварительные)

| ID | Ограничение | Статус и происхождение |
|---|---|---|
| NFR-01 | Страница адаптируется к мобильным экранам без горизонтальной прокрутки всей страницы | [С+Н]; минимальную ширину экрана согласовать |
| NFR-02 | Приложение может устанавливаться как PWA | [С]; отдельное предложение, не обязательное условие M1-01; offline не обещается |
| NFR-03 | При объёме 100 000 обращений API списка на 20 записей отвечает не более чем за 1,5 с для 95% запросов при согласованной нагрузке | 1,5 с [С]; p95, условия нагрузки и измерение — [Н]; целевое значение должно быть утверждено заказчиком |

**[С+Н]** Защищённые обращения нельзя получать без необходимых серверных прав. Конкретный механизм JWT/cookie пока не утверждён и не является заменой проверке доступа.

## 4. Сценарии приёмки (в совместной редакции)

**AC-01 — фильтр.** [С+Н] Дано: 20 обращений, 7 со статусом `new`. Когда: менеджер выбирает `new`. Тогда: frontend запрашивает отфильтрованный сервером результат и отображает только 7 обращений; остальные не удаляются.

**AC-02 — изменение статуса.** [С+Н] Дано: обращение `new`. Когда: менеджер меняет его статус на `closed` и сервер подтверждает изменение. Тогда: обращение больше не входит в выборку `new`, появляется в `closed`, история сохраняется. Это сценарий будущей мутации, не GET списка.

**AC-03 — пустая выборка.** [С+Н] Дано: подходящих обращений нет. Когда: API отвечает `200` с `items: []`. Тогда: показываем сообщение об отсутствии результатов, не выдаём это за сбой сервера.

**AC-04 — ошибка сервера.** [Н] Дано: API списка возвращает `500`. Когда: запрос завершается ошибкой. Тогда: показываем ошибку и возможность повторить запрос, но **не** сообщение «обращений нет». Студент первоначально смешал эти состояния; закрепить отдельно.

**AC-05 — истекшая сессия.** [С+Н] Дано: сессия менеджера недействительна. Когда: он открывает защищённое обращение. Тогда: защищённые данные не показываются, предлагается повторный вход.

**AC-06 — пагинация.** [С+Н] Дано: менеджер на странице 3. Когда: выбирает другой статус. Тогда: текущая страница сбрасывается на 1; выбранный фильтр сохраняется в URL [Н].

**AC-07 — неудачная отправка.** [С+Н] Дано: менеджер отправляет ответ клиенту. Когда: сервер не подтверждает отправку. Тогда: сообщение визуально помечается как неотправленное и допускает повтор [С]; точные правила повторов/идемпотентности согласовать [Н].
