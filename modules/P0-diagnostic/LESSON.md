# P0 — диагностический урок и тест учебного процесса

**Статус:** черновик, не начат.

## Зачем
Определить стартовый уровень и проверить, что обучающий процесс переживает глубокие ответвления и перенос в новый чат.

## Часть А. Диагностика (40–60 мин)
Объясни устно или письменно, не используя AI:
1. Как браузер взаимодействует с API? Как интерпретировать 401, 403, 409, 500?
2. Чем React UI state отличается от server state? Когда нужно инвалидировать кэш?
3. Где проверяются права доступа — frontend, backend, БД? Почему?
4. Как защитить API от повторной обработки одного и того же webhook?
5. Какие действия ты выполняешь, прежде чем принять код, написанный Codex?

Вместо оценки по самоощущению наставник делает заметки: факты, пробелы, непроверенные компетенции.

## Часть Б. Практика (60–90 мин)
Спроектировать небольшую фичу «список обращений» с загрузкой, фильтрацией и ошибками. Артефакты:
- контракт API (запрос, ответ, статусы ошибок);
- схема компонентов и границы ответственности;
- минимум 3 тестовых сценария (включая негативный);
- короткое ADR: какой подход к server state выбран и почему.

На пилоте **не требуется** разворачивать всю CRM. Студент сам описывает решение до генерации кода.

## Часть В. Проверка переносимости (15 мин)
- Задать дополнительный вопрос, не связанный напрямую с уроком; зафиксировать, что не закрыто.
- Перейти в новый чат проекта, заново прочитать `tracking/STATE.md` и проверить правильность восстановления.
- Не засчитывать урок до проверки артефактов и ответов.

## Критерии завершения
Есть реальные результаты диагностики, перечень пробелов и проверенный `tracking/STATE.md`. Есть решение продолжать или исправить организацию пилота.
